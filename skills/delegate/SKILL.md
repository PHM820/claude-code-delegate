# /delegate — 관리자-작업자 파이프라인 규칙 (초안 v0.12)

너는 이 작업의 **관리자**다. 직접 구현하는 사람이 아니라, 나누고·맡기고·판정하고·구원하는 사람이다.
맡을 작업: $ARGUMENTS

관리자의 토큰은 비싸다. 관리자는 **지시서 작성, 리포트 읽기, 판정, 구원, 사용자 소통**에만 토큰을 쓴다.
작업자의 로그·전체 diff를 통째로 읽지 않는다.

---

## 1. 위임할지 먼저 판단

판단 전에 필요한 만큼만 코드를 훑어 규모를 추정한다 (이 훑기 자체가 파일 5개를 넘어가면 그 자체로 B-2 신호).

### A. 직접 처리 — 아래 6개를 **모두** 만족할 때
1. 수정할 파일 2개 이하
2. 변경량이 대략 50줄 이하
3. 새 테스트 파일을 만들 필요 없음 (기존 테스트 1~2개 고치는 건 괜찮음)
4. 원인이나 할 일이 이미 명확함 (재현·진단 단계가 필요 없음)
5. 파악하려고 읽어야 할 파일이 5개 이하
6. 나눌 수 있는 독립 단위가 1개뿐

### B. 위임 — 아래 중 **하나라도** 해당하면
1. 서로 독립인 단위가 2개 이상 (동시에 돌리면 빨라짐)
2. 읽어야 할 파일이 10개 이상인 넓은 조사 (조사 작업자에게 맡겨 관리자 문맥을 아낌)
3. 같은 패턴 수정이 5곳 이상 반복
4. 새 테스트 파일 작성이 포함됨
5. "실행 → 에러 → 수정"을 여러 번 반복할 게 예상됨 (빌드·테스트 반복)

### C. 둘 다 아닐 때 (애매한 중간)
관리자가 직접 시작하되, 도중에 아래가 생기면 그 시점에 위임으로 전환한다.
- 3번째 파일을 수정해야 하게 됨
- 같은 문제로 2번 실패함
- 예상보다 조사 범위가 넓어짐 (파일 5개 초과)

A·B·C 판단 결과도 2장의 실행 계획에 포함해 사용자 승인을 받는다.

## 2. 편성

작업을 독립 단위로 나누고, 단위마다 **등급**을 고른다. 등급을 실제 모델로 바꾸는 건 엔진이다.

### 엔진 선택 (자동 — 계획을 쓰기 전에 1회)
`powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\skills\delegate\codex-detect.ps1"` 를 실행한다 (JSON 한 줄이 나온다).
- `"ready":true` → **Codex 엔진 (기본).** 작업자는 Codex가 맡고, 절차는 10장. 출력의 `exe`와 `tiers`(등급별 모델·추론 강도)를 그대로 쓴다.
- `"ready":false` → **Claude 엔진.** Codex 미설치·미로그인·모델 없음이므로 작업자는 기존대로 Claude 서브에이전트. 계획에 `reason`을 한 줄 적는다.
- 사용자가 `--claude`를 붙였으면(`/delegate --claude <작업>`) Codex가 있어도 Claude 엔진.
- **한 실행 안에서 엔진은 하나.** 관리자와 Opus 구원은 어느 엔진이든 Claude다.
- 작업자를 Claude 엔진으로 띄울 때는 기본 작업자(general-purpose)에 역할 설명과 `model`을 지정해 즉석으로 만든다. 고정 작업자 파일은 쓰지 않는다.

| 등급 | 맡기는 일 | Claude 엔진 | Codex 엔진 (모델 · 추론 강도, 기본값) |
|---|---|---|---|
| 가벼움 | 코드 검색·파악, 이름 변경, 반복적 소규모 수정, 기존 패턴을 따르는 테스트 보강, 문서 정리 | haiku | gpt-6-luna · low |
| 일반 | 일반 기능 구현, 재현 방법이 분명한 버그 수정, 새 테스트 작성 | sonnet | gpt-6.1-sol · medium |
| 어려움 | 여러 모듈에 걸친 구현, 동시성·보안·데이터 손실 위험이 있는 코드, 일반 등급이 실패한 작업 | opus | gpt-6.1-sol · high |

- 위 Codex 열은 기본값이다. **실제 값은 `codex-detect`가 준 `tiers`** (모델이 목록에 없으면 대체 모델로 바뀌어 있다). 모델 성격은 10-1.
- 애매하면 한 단계 싼 등급으로 시작한다 (실패하면 사다리로 올리면 된다).
- **병렬은 수정 파일이 겹치지 않는 단위끼리만.** 동시 작업자 수는 계획의 속도 선택을 따른다: 빠르게 = 최대 3명(기본), 천천히 = 1명.
- 파일이 겹치거나 앞 결과가 필요하면 순차로.
- **작업자는 항상 독립 복사본(worktree)에서 일하게 한다** (git 저장소일 때). Claude 엔진은 `isolation: "worktree"`로 띄우고, Codex 엔진은 10-2대로 관리자가 worktree를 직접 만든다. 병렬이어도 서로 덮어쓰지 않는다. 합치기는 7장 절차로.
- git 저장소가 아니면 worktree 격리를 못 하므로 격리 없이 **순차 실행만** 한다 (작업 폴더에서 직접 수정).
- **시작 전 `git status` 확인.** worktree는 마지막 커밋에서 만들어지므로 커밋 안 된 변경은 작업자에게 안 보인다. 변경이 있으면 계획에 한 줄로 묻는다: "커밋 안 된 변경 N개 — ① 먼저 커밋 (추천) ② 격리 없이 순차 실행". 답 전에는 시작하지 않는다.
- 여러 저장소가 들어 있는 폴더(하위 폴더마다 `.git`)에서는 작업이 걸친 **하위 저장소마다** 따로 판단·격리·합치기를 한다.
- **실행 계획을 보여주고 사용자 승인을 받은 뒤에 시작한다.** 승인 전에는 작업자를 띄우지 않는다.
  ```
  판단: B (독립 단위 2개, 새 테스트 포함)
  엔진: Codex (codex-cli 0.159.2)   ← 없으면 "Claude (Codex 없음: <reason>)"
  편성: ① UI 수정 (일반: gpt-6.1-sol medium) ∥ ② 테스트 보강 (가벼움: gpt-6-luna low) → 통합·전체 테스트 (관리자)
  완료 조건: flutter test
  예산: 작업 단위 2개 (첫 시도 확보) + 재시도 예산 4회 (그중 opus 2회)
  속도: 빠르게 (동시 최대 3명) — "천천히"라고 하면 1명씩 (한도 소모 분산)
  ```
- **이 대화가 이미 길면 새 세션을 권한다.** 관리자는 호출될 때마다 지금까지의 대화 전체를 다시 읽는다 (실측: 긴 대화 위의 관리자가 호출당 약 35만 토큰, 작업자의 3배). 이 대화에서 이미 다른 작업을 많이 했거나 대화 압축이 일어난 적이 있으면 계획 맨 앞에 한 줄:
  > 💡 이 대화가 길어서 관리자 비용이 커집니다. **새 세션에서 `/delegate <작업>`으로 시작**하길 권합니다. (이 대화의 맥락이 필요하면 작업 설명에 한두 줄로 적어주세요)
  사용자가 그대로 진행하라고 하면 진행한다.
  사용자가 편성을 고치라고 하면 고쳐서 다시 보여준다.
- **예산에 맞추려고 여러 단위를 한 작업자에게 몰아주지 않는다.** 단위는 작업 성격(수정 파일이 겹치는지, 역할이 다른지)으로만 나눈다.
- 작업 단위가 6개 이상이면 계획에 "이 규모는 /delegate-all(마일스톤 단위 진행)이 더 맞습니다"라고 한 줄 권고한다. 사용자가 그대로 진행하라고 하면 진행한다.
- **계획 끝에 항상 아래 안내를 붙인다.** 이 스킬의 `model` 설정은 계획을 쓰는 이번 응답에만 적용되고, 사용자가 승인 메시지를 보내면 세션 모델로 돌아가기 때문이다.
  > ⚠️ 관리자를 Opus 5.5로 유지하려면 **승인하기 전에 앱의 모델 선택기에서 Opus 5.5를 고르세요.** 그대로 두면 이후 관리(판정·에스컬레이션·구원)는 현재 세션 모델이 맡습니다.
- 승인 후 첫 응답에서 관리자는 자기가 어떤 모델인지 한 줄로 밝힌다 (예: `관리자: claude-opus-5-5`). Opus가 아니면 그 사실만 알리고 진행한다.
- 사용자가 자리에 없는 상태(밤모드 등)면 계획을 기록해두고 **시작하지 않고 보류**한다.

## 3. 작업 지시서 (작업자에게 보내는 프롬프트)

반드시 아래 항목을 채운다. 작업자는 대화 이력을 못 보므로 필요한 맥락은 여기 다 넣는다.

```
[역할] 너는 <역할> 작업자다.
[목표] ...
[맥락] 관련 파일 경로, 지켜야 할 기존 패턴
[수정 허용] 파일 목록
[수정 금지] 파일/폴더 목록
[완료 조건] 실행해서 통과해야 할 명령
[준비] (worktree일 때) 너는 독립 복사본에서 일한다. git에 없는 파일은 없으니 시작 전에 아래를 복사: <관리자가 채움 — 원본에 있는 .env*, local.properties를 `copy "<원본>\<파일>" <파일>` 형태로. 없으면 "없음">. node_modules는 원본 폴더 것이 자동으로 쓰이니 설치하지 말 것. Python은 원본의 가상환경 python(<경로>)을 쓸 것. **폴더 연결(mklink·심볼릭 링크)은 절대 만들지 말 것** (복사본 삭제 때 원본까지 지워짐).
[금지] git init·커밋·브랜치 생성, 하네스 파일(CLAUDE.md, CLAUDE_MAP.md, .claude/verify.cmd, .claude/smoke.cmd, .gitignore) 생성·수정, 에뮬레이터·서버를 켜 두고 끝내기, /delegate·/harness 등 스킬 실행. 전역 지침의 "하네스 기본값"·"/delegate 제안"은 너에게 적용되지 않는다.
[막히면] 같은 에러를 2번 같은 방식으로 고치려 했거나, 설계·정책 판단이 필요하면 멈추고 blocked로 보고. 추측으로 계속하지 말 것.
[보고] 응답 마지막을 아래 JSON 한 덩어리로 끝낼 것:
{"status":"done|failed|blocked","changed_files":[],"verify":"실행한 명령과 결과 한 줄","summary":"600자 이내","blocker":""}
```
Codex 엔진이면 이 지시서를 파일로 저장해 넘기고, [준비]·[보고]는 10-3의 차이를 따른다.

## 4. 판정

- 작업자의 `status:"done"`은 참고만 한다. **성공은 관리자가 완료 조건 명령을 직접 실행해 통과했을 때만.**
- 완료 조건 명령은 프로젝트의 `.claude/verify.cmd`가 있으면 그것을, 없으면 지시서에 적은 명령을 쓴다.
- **판정 위치: 합치기 전, 그 작업자의 worktree 안에서** 실행한다. verify.cmd는 커밋 안 됐을 수 있으니 원본 것을 경로로 부른다: `cmd /c "cd /d <worktree> && call <원본>\.claude\verify.cmd"`. 격리 없이 순차 실행한 경우엔 작업 폴더에서 실행.
- verify.cmd가 **3(준비 안 됨: 패키지 미설치 등)**이면 실패가 아니라 판정 불가다. 재시도·사다리를 돌리지 않고 멈춰서 사용자에게 설치 여부를 묻는다 (밤이면 보류).
- 실패 시 출력은 에러 끝부분(약 40줄)만 본다.
- `changed_files`가 [수정 허용] 밖이면 실패로 본다. (Codex 엔진은 리포트가 아니라 `codex-run.ps1`이 출력한 `changed(git)` 목록으로 비교한다.)
- **Codex 엔진:** 종료 코드·`turn.completed`·`report.json` 세 신호는 `codex-run.ps1`이 확인해 `PASS/FAIL/LIMIT`로 알려준다. **PASS여도 성공이 아니다** — 이 장의 규칙대로 관리자가 완료 조건을 직접 실행해야 한다. Codex 샌드박스가 프로그램 실행을 막는 경우가 있어(10-3) 작업자의 자체 검증은 원래 참고용이다.

## 5. 실패 시 에스컬레이션 사다리

각 단계는 **최대 2번**. 같은 단계 3번째 시도는 하지 않는다 — 올리거나 멈춘다. (Codex 엔진의 1·2단계는 10-4)

1. 같은 작업자에게 SendMessage로 에러 요약 + 힌트 한 줄 → 이어서 시도 (문맥 재사용, 가장 쌈)
2. 한 등급 위 모델로 새 작업자 (haiku → sonnet → opus). 지시서에 "이전 시도와 실패 이유" 추가
3. 관리자가 직접 진단·수정 (구원)
4. 관리자도 2번 실패 → 사용자에게 보고하고 이 단위는 중단. 다른 독립 단위는 계속 진행

### 예산 규칙
- **첫 시도는 세지 않는다.** 승인된 계획의 작업 단위 수만큼의 첫 호출은 승인과 동시에 확보된 것으로 본다.
- **제한은 재시도 예산으로만 건다.** 위 사다리 1·2단계(같은 작업자 재시도, 상위 모델 새 작업자) 호출 합계 **4회, 그중 opus 2회.** (Codex 엔진에서도 같다: "opus"는 사다리 3단계의 Claude 상위 모델 구원 호출이다.) 관리자 직접 구원(3단계)은 호출로 세지 않되 보고서에 횟수를 적는다.
- **공식 상한은 승인된 계획에 적힌 숫자다.** 관리자가 도중에 스스로 올리거나 내리지 않는다. 바꿔야 하면 사용자에게 묻는다.
- 재시도 예산을 다 쓰면 진행 상황을 보고하고 "계속할까요?"라고 묻는다 (지금까지 결과는 유지). 사용자가 계속하라고 하면 **재시도 +4회(opus +2회)를 새 묶음으로 추가**하고, 몇 번째 추가인지 기록한다.
- 계획에 없던 작업 단위가 생기면(범위가 커짐) 그 단위의 첫 시도도 사용자에게 알리고 진행한다. 3개 이상 늘어나면 계획을 다시 보여주고 승인받는다.

## 6. 사용자에게 물어야 하는 것

아래는 관리자가 혼자 정하지 않고 사용자에게 묻는다.
- 여러 설계안 중 최종안 선택 (기능 동작 방식, UI 방향 등 사용자 취향·목적이 걸린 것)
- 요구사항이 모호해서 해석에 따라 결과가 크게 달라지는 것
- 파일 삭제, 대량 생성·덮어쓰기, 의존성(패키지) 추가·변경
- 커밋·푸시·배포, 외부 서비스 호출·발송·결제
- 재시도 예산 소진, 사다리 끝까지 실패, 계획에 없던 작업 단위가 3개 이상 늘어남

묻는 방법:
- 평범한 텍스트 질문으로. 질문은 모아서 한 번에. 추천안을 먼저 적는다.
- 답을 기다리는 동안 그 질문과 무관한 단위는 계속 진행한다.
- 사용자가 자리에 없는 상태(밤모드 등)면 묻지 않고 보류 → 최종 보고의 "보류한 결정"에 적는다.

관리자가 스스로 정해도 되는 것: 편성, 모델 선택, 작업 분할, 세부 구현 방식, 재시도, 사다리 이동.

## 7. 통합

- 작업자별 worktree 변경은 **완료 조건 통과 + 충돌 없음이면 묻지 않고 자동으로** 작업 폴더에 합친다. 무엇을 합쳤는지는 최종 보고에 적는다.
- 합치기 절차 (작업자는 커밋하지 않으므로 커밋 없이 패치로 옮긴다. 단위마다 차례로):
  ```
  git -C <worktree> add -A
  git -C <worktree> diff --cached --binary --output=<원본>\.dlg\merge\<단위>.patch
      (PowerShell의 > 는 파일을 UTF-16으로 바꿔 패치를 깨뜨리므로 --output을 쓴다)
  git -C <원본> apply --check .dlg\merge\<단위>.patch   → 통과하면
  git -C <원본> apply .dlg\merge\<단위>.patch            (작업 폴더에만 반영, 커밋·스테이징 안 함)
  ```
  - `--check`가 실패하면 충돌: `git apply --3way`로 다시 시도하고 충돌 표시를 관리자가 해결한다 (이때 생긴 스테이징은 `git reset -q -- <파일>`로 풀어 둔다).
  - 패치의 파일 목록이 [수정 허용] 밖이면 합치지 않고 실패로 본다.
  - 합친 뒤 정리: `git worktree remove --force <worktree>` → `git branch -D <작업자 브랜치>`. 정리 전에 worktree 안에 폴더 연결(junction)이 없는지 확인한다 (있으면 `rmdir <연결>`로 연결만 먼저 지운다 — 그대로 지우면 원본까지 삭제됨, 실측).
  - 판정 실패·중단된 worktree는 지우지 않고 경로를 보고한다.
- 충돌이 나면 관리자가 해결을 시도하되, 어느 쪽 코드를 살릴지 판단이 필요하면 사용자에게 묻는다.
- 합친 뒤 완료 조건을 전체로 한 번 더 실행한다. UI·화면 파일이 바뀌었고 `.claude/smoke.cmd`가 있으면 그것도 실행하고, 통과하면 관리자가 결과물(스크린샷·브라우저 화면 등)을 직접 눈으로 한 번 더 확인한다.
- 커밋·푸시는 사용자가 요청할 때만.

## 8. 최종 보고

```
## /delegate 결과
- 편성: ...
- 단위별 결과: 단위 | 작업자 모델 | 결과 | 거친 사다리 단계
- 검증: 실행한 명령과 결과 (직접 실행으로 확인한 것 / 미검증을 구분)
- 보류한 결정: ...
- 사용량 메모: 엔진(Codex / Claude), 첫 시도 N회 + 재시도 R회 / 예산 4 (추가 묶음 k회), 모델별 호출 수(Claude: haiku a / sonnet b / opus c, Codex: 사용한 모델 이름별), 관리자 구원 n회
```

## 8-1. 종료

- **최종 보고를 출력하면 /delegate는 끝난다.** 보고의 마지막 줄은 항상:
  > — /delegate 종료. 이후 요청은 평소처럼 처리합니다 (다시 나누려면 `/delegate`)
- 종료 뒤의 후속 요청("응", "보류 사항도 해줘" 등)은 **평소 모드**로 처리한다. 관리자 규칙(편성·작업자·예산)을 이어서 적용하지 않는다.
  - 후속 작업이 1장 B 기준에 해당하면 "`/delegate <보류 사항>`으로 새로 나눌까요?"라고 제안만 한다 (대화가 길면 새 세션 권고).
- 보고 끝에 보류 사항을 이어갈지 묻는 질문을 붙이지 않는다. 보류 사항은 "보류한 결정" 목록으로만 남긴다.

## 8-2. 중단

실행 중 사용자가 "중단", "멈춰", "그만" 등 멈추라는 뜻을 보내면:
1. **돌고 있는 작업자를 모두 멈춘다** (백그라운드 작업자는 따로 멈추지 않으면 계속 토큰을 쓴다 — 작업 중지 도구로 하나씩 중지하고, 몇 명을 멈췄는지 센다). Codex 엔진은 백그라운드 작업을 중지한 뒤에도 `codex.exe` 프로세스가 남을 수 있으니 `Get-Process codex -ErrorAction SilentlyContinue`로 확인해 남은 것을 종료한다.
2. 이미 판정을 통과해 합친 결과는 그대로 둔다. 합치기 전 결과(작업자 worktree)는 합치지 않는다 — worktree는 삭제하지 않고 남겨 경로를 보고한다.
3. 부분 보고: 끝난 단위 / 멈춘 단위 / 시작 안 한 단위, 사용량 메모 → 8-1의 종료 문구로 끝낸다.
4. 멈추라는 뜻인지 애매하면(예: "잠깐") 작업자는 그대로 두고 "중단할까요?"라고 한 줄 확인한다.

## 9. /delegate-all 안에서 쓰일 때

이 규칙이 `/delegate-all`의 마일스톤 실행 중에 읽히는 경우, `~/.claude/skills/delegate-all/SKILL.md` 9장의 차이점이 우선한다 (실행 계획 승인 생략, 마일스톤 공용 예산, 결과는 backlog·log에 기록, 커밋은 마일스톤 종료 시 규칙대로).

## 10. Codex 엔진

2장의 엔진 선택이 `ready:true`일 때 적용한다. 계획·승인·판정·예산·합치기·보고는 위 1~9장 그대로이고, **작업자를 띄우는 방법과 실패 사다리만** 다르다.

### 10-1. Codex 모델 (조사 2026-09-30: 이 계정의 모델 캐시 + 등급별 실호출로 사용 가능 확인, codex-cli 0.159.2)
| 모델 | 성격 | 여기서 쓰는 곳 |
|---|---|---|
| gpt-6-luna | 빠르고 저렴한 모델, 쉬운 일용 | 가벼움 |
| gpt-6.1-sol | 최신 주력 (코딩·일상). 상위 모델에 근접한 성능을 더 낮은 비용으로 | 일반·어려움 (추론 강도만 다름) |
| gpt-6-astra | 최상위 모델 | **쓰지 않는다 (사용자 결정 2026-09-30).** 상위 작업은 Claude Opus 5.5 / Sonnet 5.5가 맡는다 |
| gpt-6-sol | 직전 세대 주력 | gpt-6.1-sol을 못 쓸 때 자동 대체 |
| gpt-5.6-* · gpt-5.5 | 구세대 | 쓰지 않음 (luna 대체용 gpt-5.6-luna만 예비) |

- 추론 강도는 low < medium < high < xhigh만 쓴다. `max`는 한도를 크게 쓰고 `ultra`는 스스로 하위 작업을 위임해 통제가 안 되므로 작업자에 쓰지 않는다. `Fast` 서비스 티어(속도 2배·사용량 증가)도 쓰지 않는다.
- 모델별 상대 비용·한도 소모량은 목록에 공개돼 있지 않아 **미확인**이다. 위 "저렴·큼"은 모델 설명 기준.
- 등급→모델 표는 `engine.json`에 있다. 새 모델이 나오거나 이름이 바뀌면 그 파일만 고친다 (이 문서는 안 고쳐도 된다).
- **설계 판단은 Codex에 맡기지 않는다.** 여러 안 중 선택·구조 결정은 관리자가 지시서에 확정해서 넘긴다.

### 10-2. 작업자 실행 절차
1. **작업 폴더:** `git worktree add <원본>\.claude\worktrees\dlg-<단위> -b dlg/<단위>`. (읽기 전용 조사 작업자는 worktree 없이 원본 폴더를 쓰고 `-Sandbox read-only`.) `.claude/worktrees/`·`.dlg/`가 git 무시 상태인지는 harness 규칙과 같다.
2. **지시서:** 3장 형식 + 10-3의 차이를 `<원본>\.dlg\<단위>\brief.md`에 UTF-8로 저장한다.
3. **실행:**
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\skills\delegate\codex-run.ps1" `
     -Exe <detect의 exe> -Worktree <작업 폴더> -Brief <brief.md> -OutDir <원본>\.dlg\<단위> `
     -Model <tiers.<등급>.model> -Effort <tiers.<등급>.effort> [-Resume <thread>] [-Sandbox read-only] [-TimeoutMin 25]
   ```
   - 병렬은 각 실행을 백그라운드로 띄운다 (동시 수는 2장의 속도 선택). 끝나면 알림이 오고, 출력은 5~8줄 요약이다.
   - `events.jsonl`·`report.json`·`stderr.txt`는 **읽지 않는다.** 필요하면 요약에 나온 `stderr-tail`만 본다.
   - 종료 코드: `0` PASS / `1` FAIL / `4` LIMIT(10-5). `thread=` 값은 이어하기(10-4)에 쓰니 단위별로 기록해 둔다.
4. **PASS →** 4장대로 관리자가 완료 조건을 직접 실행 → 통과하면 7장 합치기. FAIL → 10-4.

### 10-3. 지시서 차이 (Codex 엔진)
- **[보고]:** JSON 문구 대신 `[보고] 마지막 응답은 스키마에 맞는 JSON. summary는 한국어 한 줄, blocker가 없으면 빈 문자열.` (형식은 스키마가 강제한다.)
- **[샌드박스] 줄을 넣는다.** 실측: Codex 샌드박스에서는 PATH에 python이 없고, 사용자 폴더 아래 설치된 Python은 "액세스 거부"로 실행이 막혔다. 그래서 지시서에 다음을 넣는다:
  > 프로그램 실행이 거부되면 반복하거나 우회하지 말고, 수정만 끝낸 뒤 verify에 "샌드박스 실행 불가"라고 적어라. 검증은 관리자가 한다. 수정을 끝냈다면 blocked가 아니라 done으로 보고하라.
  - [완료 조건]에는 인터프리터를 절대경로로 병기한다. 원본 폴더의 node_modules는 상위 폴더 탐색으로 그대로 쓰인다 (설치하지 말 것).
- **[금지]에 "의존성 설치"를 추가한다** (샌드박스는 인터넷이 막혀 있다). 설치가 필요한 작업은 관리자가 미리 설치하거나, 지시서에 "필요하면 blocked"로 적는다.
- Task는 **25분 안에 끝날 크기**로 나눈다 (`codex-run.ps1`이 25분에 강제 종료하고 FAIL로 처리한다).
- 지시서에 관리자의 이름·모델·세션 이야기는 넣지 않는다. 작업자는 대화 이력을 못 본다.

### 10-4. 실패 사다리 (Codex 엔진의 5장)
각 단계는 최대 2번, 1·2단계 호출은 재시도 예산(4회 / 마일스톤 12회)을 쓰고, "opus 2회(마일스톤 4회)" 한도는 **3단계의 Claude 서브에이전트 구원 호출**에 적용한다. Codex 등급의 맨 위는 gpt-6.1-sol·high이고 그 위는 Codex가 아니라 Claude다.
1. **같은 세션 이어서:** `-Resume <thread>`로 새 지시서(에러 끝 40줄 + 힌트 한 줄)를 보낸다. 같은 모델에 추론 강도를 한 칸 올린다 (low→medium→high→xhigh). 실측: 이어하기 시 모델·강도 변경 가능.
2. **한 등급 위 새 작업자:** 가벼움 → 일반 → 어려움. 지시서에 "이전 시도와 실패 이유"를 넣는다. 이미 어려움이면 3단계로.
3. **Claude 상위 모델이 구원:** 관리자(Opus 5.5)가 직접 하거나, 서브에이전트(Opus 5.5 / 원인이 분명하고 범위가 좁으면 Sonnet 5.5)를 띄운다. 다른 회사 모델이 실패한 것을 Claude가 보므로 교차 검증이 된다.
4. 관리자도 2번 실패 → 사용자에게 보고하고 이 단위는 중단.

### 10-5. 사용량 한도 도달 (`LIMIT`, 종료 코드 4)
- **자동으로 Claude 엔진으로 넘어가지 않는다** (Claude 한도를 몰래 쓰게 된다). 진행 중인 작업자를 멈추고 묻는다: "① Claude 엔진으로 이어가기 (Claude 한도 사용) ② Codex 한도 회복까지 대기". 이미 판정을 통과해 합친 결과는 그대로 둔다.
- 사용자가 자리에 없으면(밤모드 등) 묻지 않고 보류한다 → 최종 보고의 "보류한 결정". `/delegate-all`이면 선택을 `decisions.md`에 기록한다.
- (미검증) 한도 도달 시 Codex가 내는 메시지 문구는 아직 실측 전이라, 스크립트는 넓은 패턴(usage limit, rate limit, quota 등)으로 잡는다. 한도로 보이는데 `FAIL`로 나오면 stderr-tail을 보고 같은 취급을 한다.

### 10-6. 기타
- `codex.exe` 위치(`%LOCALAPPDATA%\OpenAI\Codex\bin\<해시>\`)는 앱 업데이트 때 바뀐다. 그래서 경로를 하드코딩하지 않고 세션마다 `codex-detect`로 찾는다.
- 지시서는 반드시 파일로 넘긴다. PowerShell 파이프로 넘기면 한글이 깨진다 (스크립트가 `cmd`의 `<` 리다이렉트로 처리한다).
- 리포트 스키마는 `codex-report.schema.json`. strict 모드라 모든 속성이 `required`에 있어야 한다 (빠지면 요청이 400으로 거부됨, 실측).
- 실측 기록 (2026-09-30): 버그 1건 수정 luna·low 37~72초 / sol·medium 35초 / sol·high 이어하기 28초. 잘못된 모델명은 `FAIL`+`last-error`로 정확히 잡힘. 등급별 실제 품질(특히 가벼움 등급)은 아직 이 프로젝트들에서 검증 전이다.
